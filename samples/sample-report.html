False positive?

No — 38 failed password attempts in 40 seconds followed by an accepted password is not a user mistyping.

Threat summary

Successful SSH brute force against the root account on n8n-VM from 185.220.101.47, a known Tor exit relay. 38 failures in 40 seconds, then an accepted password at 09:14:52 UTC. The attacker now holds valid root credentials on this host. Severity 8/10.

Multi-source intel

  • VirusTotal: 7 engines flag the address as malicious, 2 as suspicious.
  • AbuseIPDB: 100% abuse confidence, 1,247 reports in 90 days. Usage type "Data Center/Web Hosting/Transit"; ISP is a Tor relay operator.
  • Combined: 85/100. Both sources agree independently — this is not a reputation artefact.

Key findings

  • 185.220.101.47 is anonymising infrastructure. No legitimate administrative access should originate here.
  • Password authentication succeeded for root directly — root SSH login and password auth are both enabled on this host.
  • MITRE T1110 (Brute Force). Follow-on T1078 (Valid Accounts) is now likely.
  • The host log pull confirms the burst pattern and shows no earlier successful login from this address.

Immediate actions

  • Treat n8n-VM as compromised. Isolate it and hunt for persistence: authorized_keys, cron, systemd units, new local users.
  • Rotate the root password and every credential stored on or reachable from this host.
  • Block 185.220.101.47 at the perimeter and kill any active session from it.
  • Sweep auth logs on every other host for the same source and pattern.

Recommendations

  • Set PermitRootLogin no and disable password authentication in sshd_config; move to key-only access.
  • Deploy fail2ban or equivalent rate limiting, and put SSH behind a VPN or bastion.

Conclusion

Confirmed successful credential-access attack from anonymising infrastructure against a privileged account. Escalate to incident response now.
